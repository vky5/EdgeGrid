# Token & secret inventory

Every credential in the system, where it lives, how it's generated, and what
happens if it leaks. Cross-reference with `auth-architecture.md` for the
flows these fit into.

| Secret | Where stored | Generated by | Read by | Blast radius if leaked |
|---|---|---|---|---|
| `NEXTAUTH_SECRET` | `web/.env.local` (server env) | You, via `openssl rand -base64 32` | NextAuth internals only | Forge any user's session JWT — full impersonation of any GitHub-linked user, including admin. Highest-value secret in the whole system. |
| `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` | `web/.env.local` | GitHub OAuth App settings | NextAuth GitHub provider | Attacker could stand up a phishing OAuth flow under your app's identity, or (with secret) exchange codes for tokens. Doesn't by itself forge sessions — still needs `NEXTAUTH_SECRET`. |
| `COORDINATOR_ADMIN_TOKEN` (gateway token) | `web/.env.local` (Next.js side); `data/admin.token` (coordinator side) | `nodeident.RandomToken(32)` in `internal/agent/build.go`, printed once to stdout on first boot | `coordFetch()` attaches it; `requireGateway()` in `internal/coordinator/router.go` checks it | **Full coordinator API access** — submit/cancel any job, approve/reject any node join, read/download any job's data and checkpoints, list all workers. Bypasses all per-user ownership checks, since those only exist in Next.js. This is the single point where "backend trust" lives. |
| `node.token` (per-node NATS password) | `node_auth` KV bucket (coordinator); `data/node.token` (on the node itself) | `nodeident.RandomToken(32)` in `joinapi.Approve` | Coordinator (to add the NATS user); the node itself | Impersonate that one worker/server on NATS — publish fake heartbeats/results, receive training jobs meant for it, read/write whatever subjects its role permits. Scoped to one node, not the whole system. |
| `cluster.secret` | `data/cluster.secret` on each server-role node | Primary coordinator generates it in `internal/agent/credentials.go`; joining server nodes receive it from `joinapi.Approve` | Any node joining as a `server` cluster peer; NATS `Cluster.Password` | **Join the NATS cluster as a full route peer**, not just a client — this is a much bigger grant than a worker token. A leaked cluster secret lets an attacker's NATS node peer into your Raft cluster, see all replicated JetStream data, and potentially participate in consensus. Single shared secret for *all* peers (not per-node), so it can't be revoked for just one bad actor without rotating it everywhere. |
| `coord.secret` | `data/coord.secret` | `nodeident.RandomToken(32)` in `internal/agent/credentials.go` for a primary coordinator | Embedded NATS setup and the coordinator's own NATS client credential | Impersonate the coordinator's own NATS client connection — read/write anything the coordinator process itself can. |
| `node.id` | `data/node.id` | `crypto/rand`, 16 bytes hex, in `nodeident.LoadOrCreate` | Not a secret by design — used as the NATS *username* and the join-request KV key | Not sensitive on its own (128 bits, unguessable), but it identifies the node throughout join, NATS auth, worker state, and dashboard views. Treat it as semi-sensitive together with `node.nonce` while a join is pending/approved. |
| `node.nonce` | `data/node.nonce` on the joining node; copied into `join_requests` KV as `poll_nonce` | `nodeident.EnsurePollNonce` during `requestAndWaitForApproval` | Joining node sends it as `X-Node-Nonce`; `joinapi.Status` checks it before returning join status/secrets | Protects `GET /join/{nodeID}`. If leaked with the node ID while approval is pending/approved, an attacker can poll the join endpoint and receive that node's NATS token/cluster secret. |
| `tailscale.ip` | `data/tailscale.ip` | Saved by `agent.NewAgent` after `tsnet.Up` returns a Tailscale IPv4 | TUI/dashboard startup uses it as a remembered reachable address | Not a secret. It reveals the node's tailnet IP, useful for operators and join routing, but it does not grant access without tailnet membership and the relevant EdgeGrid credentials. |
| `tsnet/` machine state | `data/tsnet/` directory | Tailscale `tsnet.Server` after login or auth-key join | `tsnet.Server` on later starts | Lets the same EdgeGrid node rejoin the tailnet without another login/key. Treat like device identity: a copied directory may let another process present as the same tailnet device, subject to Tailscale policy. |
| `TS_AUTHKEY` / `--ts-authkey` / minted Tailscale auth key | Operator-provided env/flag on the joining node; shown once in the Tokens tab when minted; raw key is **not** stored by EdgeGrid after minting | Tailscale API, via `tailscaleapi.CreateKey`; EdgeGrid calls it from `POST /admin/tokens/mint` | `tsnet.Server.AuthKey` consumes it to join the tailnet | Grants a new device tailnet membership. EdgeGrid mints single-use, pre-authorized, tagged, non-ephemeral keys, so one leak can admit one device until used or revoked. It does not by itself approve the EdgeGrid join request or grant NATS access. |
| `ts_api_client_id` / `ts_api_client_secret` | Primary coordinator's data dir, set in the TUI Settings tab | Tailscale OAuth client credentials, created in Tailscale admin console | `tailscaleapi.LoadCredentials`; used by `POST /admin/tokens/mint` and revoke | Can mint/revoke Tailscale auth keys for the configured tailnet scope. A leak lets an attacker create tailnet join keys, but still does not grant the EdgeGrid admin token, node token, or cluster secret. |
| `ts_api_tailnet` | Primary coordinator's data dir, set in Settings | Operator config | `tailscaleapi.LoadCredentials` builds `/tailnet/{tailnet}/keys` API URLs | Not a secret. Selects which tailnet the OAuth client mints keys for. Wrong value breaks mint/revoke. |
| `ts_api_tag` | Primary coordinator's data dir, set in Settings | Operator config | `tailscaleapi.CreateKey` includes it in minted key capabilities | Usually not secret. Controls the tag attached to newly joined devices. It is security-relevant because Tailscale ACLs can grant permissions by tag. |
| Tailscale OAuth access token | In memory only inside `tailscaleapi.Client` | Exchanged from `ts_api_client_id`/`ts_api_client_secret` by `accessToken()` | Tailscale API requests for key mint/revoke | Short-lived bearer for the Tailscale management API. If captured from process memory/logging, it can do whatever the OAuth client scope allows until expiry. EdgeGrid does not persist or log it. |
| `minted_tokens` records | NATS KV bucket `minted_tokens` | `tokenapi.Mint` after a Tailscale key is created | Tokens tab, `tokenapi.List`, `tokenapi.Revoke` | Stores metadata and `sha256(rawAuthKey)`, never the raw auth key. A leak does not let someone join the tailnet, but it can reveal mint history and correlate a minted key to the node that later used it. |
| `ADMIN_GITHUB_USERNAME` / `NEXT_PUBLIC_ADMIN_GITHUB_USERNAME` | `web/.env.local` | You set it manually | `isAdmin()` (`web/lib/auth.ts:35`) | Not a secret (it's a username, and the `NEXT_PUBLIC_` copy is shipped to the browser on purpose for UI toggling). Authorization decisions use the server-only copy, so this can't be spoofed by editing client-visible env — only by controlling the server's actual environment. |

## Where secrets live on disk

All of the coordinator/node-side secrets above land in the process's
`--data-dir` (default `data/`) as flat files, written 0600 via
`nodeident.SaveToken` (`internal/nodeident/ident.go:68`):

```
data/
  admin.token      # gateway token (coordinator)
  coord.secret     # coordinator's own NATS client credential
  cluster.secret   # NATS cluster-route shared password
  node.token       # this node's NATS client credential
  node.id          # this node's identifier (not secret, but semi-sensitive)
  node.nonce       # proves this node may poll its join result
  tailscale.ip     # remembered tsnet IPv4, not a secret
  tsnet/           # Tailscale device state
  ts_api_client_id      # primary coordinator: Tailscale OAuth client id
  ts_api_client_secret  # primary coordinator: Tailscale OAuth client secret
  ts_api_tailnet        # primary coordinator: tailnet name/id
  ts_api_tag            # primary coordinator: tag for minted auth keys
  nats/            # JetStream storage — gitignored today
```

The credential files above should stay out of git. The repository currently
ignores the default `data/` directory as a whole; if you run with a custom
`--data-dir`, treat that directory the same way.

## What each credential powers

Use this as the quick mental model:

- **`admin.token`** opens the coordinator HTTP API. It is the broadest EdgeGrid
  application credential.
- **`node.id` + `node.nonce`** let a not-yet-approved node safely ask,
  "was my join request approved, and what credential did I receive?"
- **`node.id` + `node.token`** are the node's NATS login after approval.
- **`coord.secret`** is the coordinator's own privileged NATS client login.
- **`cluster.secret`** admits a server-role node as a NATS cluster route peer.
- **Tailscale auth keys** admit devices to the private transport network.
- **Tailscale OAuth credentials** let the primary coordinator mint/revoke those
  Tailscale auth keys.
- **`tsnet/` state** keeps this process logged in as the same tailnet device.
- **`minted_tokens`** tracks Tailscale key records and activation status; it
  does not contain usable join keys.

Tailscale access and EdgeGrid approval are separate. A minted Tailscale auth
key gets the process onto the tailnet so it can reach the coordinator over the
private network; the admin still has to approve the EdgeGrid join request
before the node receives `node.token` or `cluster.secret`.

## Rotation story

There isn't one, currently. Every secret above is generate-once,
persist-to-disk, reuse-forever, except for Tailscale auth keys minted through
the Tokens tab. Those are single-use and can be revoked before use via
`POST /admin/tokens/{id}/revoke`; revoking one does **not** remove a device
that already joined the tailnet with it.

There is still no general EdgeGrid rotation tooling: no way to revoke a single
compromised node's `node.token` without manually editing the `node_auth` KV and
hot-reloading NATS users, and no one-click rotation for `admin.token`,
`coord.secret`, or `cluster.secret`. Worth keeping in mind if a laptop or disk
ever gets shared/reimaged without wiping `data/` first.
